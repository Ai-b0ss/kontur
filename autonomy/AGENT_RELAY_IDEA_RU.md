# Обычный ChatGPT web relay — текущая простая карта

Это вспомогательный механизм ради автономности, а не новый главный продукт. Qwen / Notion / Kontur остаются главной работой.

## Зачем

Пять Scheduled Tasks дают пять периодических пробуждений, но отдельный запуск может закончиться рано. Идея relay: внешний исполнитель может написать новое пользовательское сообщение прямо в заранее выбранный обычный чат `chatgpt.com`, чтобы дать этому чату ещё один ход работы без участия владельца.

Это НЕ OpenAI API и НЕ Work mode. Это обычный ChatGPT web UI под собственной авторизованной сессией владельца.

## Доступ к ChatGPT

Не хранить отдельный открытый `CHATGPT_TOKEN`.

Хранится переносимое browser storage state (cookies + web storage/IndexedDB + URL выбранного чата), и только в зашифрованном виде:

`.runtime-state/chatgpt-web-session-v1.json.gpg`

Он идёт через существующий Git LFS.

Предпочтительный ключ — уже существующий CircleCI secret:
`RUNTIME_STATE_KEY`.

Если старый Qwen key локально физически не найден, предусмотрен запасной секрет:
`CHATGPT_RUNTIME_STATE_KEY`.

По состоянию на 2026-08-19 encrypted ChatGPT session ЕЩЁ НЕ создана/не опубликована. Это единственный кусок, который невозможно изготовить без одноразового входа владельца в собственный ChatGPT на ПК.

## Защита от дублей

Каждое внешнее сообщение получает:
`[relay-id:<уникальный-id>]`.

Перед отправкой браузер ищет этот id среди последних пользовательских сообщений в самом целевом чате. Если он уже там — второй раз не отправляет, даже если прошлый CircleCI успел написать сообщение, но не успел отметить доставку в GitHub.

Успех считается только если:
1. новое пользовательское сообщение реально появилось в DOM целевого чата;
2. после него реально начался новый assistant-turn.

Текст ответа для подтверждения старта не требуется читать.

## Как реально запускаем CircleCI

Отдельная relay-ветка сама по себе не получила CircleCI statuses, даже после служебного PR. Поэтому не тратить дальше время на попытки заставить CircleCI отдельно триггерить её.

Вместо этого relay подключён к уже доказанно работающей Qwen-ветке:
`autopilot/qwen-runtime-preflight-20260818`.

Стартовая точка моста:
`0d9106f6af1f3a305949e60ece57e44ad67895eb`.

В уже существующий CircleCI job `qwen-long-soak-policy-gate` добавлен второй шаг:
`Ordinary ChatGPT relay pulse`.

Это специально сделано внутри уже запускаемой маленькой CircleCI-машины, чтобы не поднимать четвёртый executor и почти не тратить дополнительные credits.

Pulse делает так:
- fetch свежей relay-ветки;
- проверяет синтаксис relay-скриптов, outbox и отсутствие plaintext secrets в Git;
- если `enabled=false`, не открывает ChatGPT и заканчивает работу;
- если `enabled=true`, берёт encrypted session + `RUNTIME_STATE_KEY`, запускает Playwright и доставляет сообщение;
- по возможности пишет `CHATGPT_RELAY_OFFLINE_GATE_PASS` / `CHATGPT_RELAY_SENT` в issue #11.

На момент записи этого файла commit `0d9106f6...` уже запушен, но его CircleCI status ещё не был виден через GitHub. Автоматизация `Qwen — пул и надёжность` получила отдельное указание проверить этот bridge на следующем запуске и минимально починить, если pulse красный. Она не должна включать live outbox до появления encrypted owner session.

## Что сейчас физически безопасно

`relay/outbox.json` пока `enabled=false`.
Encrypted ChatGPT session отсутствует.

Поэтому текущий код НЕ МОЖЕТ отправить сообщение в обычный ChatGPT: он способен только пройти офлайн-проверку relay-каркаса.

## Первый реальный тест, когда будет ПК

Нужен только один человеческий вход:

1. Открыть локально ветку `autopilot/chatgpt-web-relay-20260819`.
2. Дважды кликнуть `CHATGPT_RELAY_FIRST_TEST.cmd`.
3. В отдельном открывшемся Chromium войти в СВОЙ ChatGPT.
4. Просто открыть выбранный обычный чат `https://chatgpt.com/c/...`.
5. Больше ничего в консоли подтверждать не нужно: скрипт сам увидит чат.
6. Он сохраняет переносимое состояние, шифрует его, удаляет plaintext и публикует encrypted bundle + уникальный тестовый outbox.
7. Следующий Qwen CircleCI pulse должен открыть этот же обычный чат и отправить `CHATGPT_RELAY_TEST_... [relay-id:...]`.
8. Relay ждёт факт старта нового ответа ассистента.

Если старый Qwen runtime key найден локально — новый секрет вообще не нужен. Если не найден — скрипт остановится ДО входа в ChatGPT и попросит один раз положить созданный ключ в CircleCI под именем `CHATGPT_RUNTIME_STATE_KEY`.

## После первого PASS

Тогда Scheduled Task / Qwen / Notion сможет оставлять короткое новое задание в `relay/outbox.json`, а уже существующий Qwen CircleCI pulse доставит его в обычный ChatGPT-чат.

Приватный большой системный промпт владельца в GitHub не нужен: он может оставаться только внутри самого целевого обычного чата. Relay отправляет лишь короткие команды продолжения.

Главный смысл: меньше времени, когда система ничего не делает только потому, что очередной Scheduled Task уже завершился.
