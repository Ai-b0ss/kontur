## Что уже есть

- локальные CAPTCHA/rate limit/expired auth не останавливают весь пул: бюджет переключений по умолчанию 4, жёсткий потолок 6;
- provider-wide WAF/trust restriction, provider pressure и неоднозначный timeout останавливают дальнейшее прощупывание соседних аккаунтов;
- новый независимый запрос выбирает давно не использовавшийся подходящий аккаунт, а существующий Qwen-тред сохраняет приоритет своего аккаунта-владельца;
- при failover незавершённой цепочки создаётся свежий Qwen-тред и один раз переносится полная локальная история;
- tool-loop продолжает работу после tool result и исправимых ошибок инструмента; обычный лимит 12 модельных ходов, жёсткий потолок 24;
- два режима системного промпта (`engineer`/`owner`) и локальные Skills уже есть;
- account JSON, основной session checkpoint и backup сохраняются crash-safe;
- provider circuit теперь не только записывается атомарно, но и очищается через `rename -> fsync каталога -> удаление tombstone`; реальная ошибка диска при очистке не маскируется как успех;
- ChatGPT relay не активная задача до появления owner session; outbox не включать.

## Эта смена

- заново прочитаны owner intent, текущая карта и handoff; проверены свежие PR #6 и `qwen-workspace` PR #5;
- на старте PR #6 уже ушёл до `93a29257d7abdf96732934bd19735c38851c7d37`: соседний рабочий уже довёл `reset/markSuccess` через `commitMutation`, а `markFailure` сохраняет копию перед публикацией в памяти, поэтому повторно эти операции не переписывались;
- взят независимый участок `src/provider-circuit.js`;
- найден реальный дефект долговечности: `clear()` удалял `provider-circuit.json` в best-effort режиме и всегда возвращал успех. При I/O-сбое процесс мог считать общий защитный контур снятым, а после перезапуска старый circuit снова появлялся с диска;
- исправлено: очистка сначала переименовывает файл в уникальный tombstone, подтверждает удаление записью каталога на диск и только потом удаляет tombstone. Если подтверждение каталога падает, прежний circuit восстанавливается и ошибка возвращается вызывающему коду;
- синхронизация каталога при записи provider circuit теперь игнорирует только реально неподдерживаемые операции (`EINVAL/ENOTSUP/EOPNOTSUPP`), а настоящий `EIO` больше не проглатывается;
- `scripts/provider-circuit-persistence-test.js` усилен: искусственный `EIO` при очистке обязан завершить `clear()` ошибкой, восстановить прежнее состояние и не оставить tombstone; нормальная очистка после этого проходит;
- коммиты этой смены: `5425b6be437ee664c1db70c6165128d92f425d89`, `a154afdd381de508499740fe8c0a33d1b82e19e8`;
- provider traffic = 0; живые аккаунты, encrypted runtime, production и relay не тронуты.
