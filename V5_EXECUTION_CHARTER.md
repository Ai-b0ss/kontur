# Контур V5 — рабочая хартия

Статус: **рабочий документ, 2026-08-07**. Направление V5 подтверждено владельцем.
Этот файл не меняет V1–V4 и не разрешает production-выпуск сам по себе.

## 1. Цель

**Контур V5 — режиссёр живой кампании одного Telegram-чата.**
Чат создаёт повод, участник за 20–90 секунд совершает ход своей птицей в
Mini App, общий мир меняется наблюдаемым образом, а личная птица развивается
месяцами.

Не строить как основу:

- FAQ, навигатор абитуриента или сервис для молчунов;
- ежедневную викторину, где вопросы являются всей игрой;
- свободно болтающего LLM-бота;
- рейтинг сообщений, рынок, передачу ресурсов или pay-to-win;
- обязательный taskboard с поручениями людей чата.

## 2. Неподвижные продуктовые правила

1. Претест выдаёт базовую птицу и склонности, а не навсегда назначенную профессию.
2. Прогресс птиц, форм и неторгуемых предметов постоянный; кампания меняется
   раз в 2–4 недели, профиль живёт месяцами.
3. Игрок может развивать несколько птиц, но активна только одна.
4. Обучение обязательно, но является одним из типов испытаний наряду с
   тактическим выбором, прогнозом и рейдом.
5. Соло-ход полноценен. Групповой рейд даёт отдельный результат, но не блокирует
   игрока в очереди.
6. Яйца — закрытый игровой ресурс для анонимных прогнозов только на безопасные
   игровые исходы; никаких ставок на людей, денег, торговли или передачи.
7. Публичный слой редкий и предметный: открытие события, вход, итог. Не более
   одного основного игрового сообщения в чат за окно события.
8. Любой эффект, награда, верный ответ и баланс вычисляются сервером.

## 3. Система из четырёх слоёв

| Слой | Ответственность | Не делает |
| --- | --- | --- |
| Движок кампании | события, карта, ход, рейд, прогресс, экономика, idempotency | не зависит от LLM |
| Mini App | личная птица, текущий ход, карта, гнездо, коллекция | не превращается в отдельную соцсеть |
| Telegram-голос | короткий анонс, кнопка входа, итог, добровольный вызов контракта | не спамит и не оценивает людей |
| LLM-режиссёр | выбирает разрешённый шаблон, тему и одну строку подачи | не судит, не награждает, не публикует сам |

## 4. Как используются доступные инструменты

| Ресурс | Когда применять | Критерий, что он остаётся в цепочке |
| --- | --- | --- |
| Codex | владелец архитектуры, кода, тестов, интеграции и выпуска | всегда: единая ответственность за итог |
| GPT Sol High | независимый дизайн-системный и кодовый review только по конкретному вопросу/диффу | находит дефекты или даёт применимый артефакт лучше локального первого прохода |
| Notion | журнал решений, каталог событий, visual references, обзор работ | не расходится с repo и ускоряет ориентацию |
| Figma Make | 2–3 визуальных направления и главный мобильный экран | выбранный макет переводится в измеримый UI, а не остаётся картинкой |
| Telegram raw corpus | точечный поиск названий инструментов и паттернов | источник имеет понятную дату, ссылку и применимость; credential-like данные исключаются |
| Free/low-cost model APIs | только после отдельной проверки текущих лимитов, условий, latency, fallback и server-side secret path | проходят маленький production-like probe без утечки ключа |

Gemini и Hyperagent исключены по решению владельца. Наличие доступа не является
причиной использовать инструмент.

## 5. Проверка провайдеров LLM

Кандидаты из находок: Groq, Cloudflare Workers AI, GitHub Models, NVIDIA NIM,
OpenRouter, Cerebras, Mistral AI, Hugging Face Inference Providers.

Перед выбором каждый кандидат получает одинаковую проверку:

1. есть ли официальный server-side API и применимая бесплатная/дешёвая квота;
2. допускают ли условия использование в Telegram-продукте;
3. выдерживает ли структурированный JSON-ответ режиссёра;
4. есть ли понятный rate limit, timeout и стоимость превышения;
5. есть ли fallback на детерминированный каталог событий;
6. можно ли хранить ключ только в Cloudflare secret, не в чате, коде или клиенте.

Провайдер не станет источником истины игры. Первый работающий V5-вертикальный
срез обязан функционировать вообще без внешней модели.

## 6. Порядок реализации

1. Зафиксировать event contract, прогрессию, экономику, антиабуз и критерии
   первого запуска в [V5_PRODUCT_SPEC.md](V5_PRODUCT_SPEC.md).
2. Смоделировать кампанию и доказать отсутствие единственной доминирующей
   тактики, выгодного скрипт-фарма и обязательного ожидания команды.
3. Получить два независимых review: системный/anti-abuse и UX/визуальный.
4. Создать визуальное направление в Figma Make: птица, карта, событие,
   экран хода, итог, состояние рейда.
5. Реализовать V5 как отдельный feature gate и новые D1-миграции; V1–V4 не
   удалять и не переписывать.
6. Добавить Telegram-режиссёра с opt-in/ограниченным набором триггеров и
   deterministic fallback.
7. Подключить выбранный LLM только после локального и staging-probe.
8. Выполнить тесты, симуляции, проверку Telegram, backup D1, deploy и
   controlled pilot.

## 7. Первый запрос внешнему reviewer'у

```text
Ты — независимый senior game-systems reviewer. Не придумывай новый продукт.
Разнеси в поисках конкретных дефектов следующий V5-контракт Telegram Mini App:
1) базовая птица из претеста; прогресс постоянный, активна одна птица;
2) в чате редко открываются события; в Mini App 20–90 секунд соло-хода;
3) действия «разведать / удержать / захватить» имеют разные серверные эффекты;
4) обучение — один из видов испытания, не вся игра;
5) редкий рейд 4–6 человек не должен блокировать соло-игру;
6) яйца — только анонимный прогноз игрового исхода;
7) LLM только выбирает готовый шаблон/тему/одну строку, не судит и не награждает;
8) один решающий ход за окно, без торговли и награды за скорость.

Дай: (a) 5 наиболее опасных exploit/boring-loop рисков; (b) минимальные
правки правил; (c) 10 критериев acceptance test. Максимум 900 слов.
```
