Сделано:
- Заново проверены текущие PR и исходники обоих Qwen-репозиториев.
- Найден и исправлен реальный дефект ротации: `generateChatID(..., targetAccount)` раньше мог сам уйти на соседний аккаунт, вернуть созданный там `chatId`, после чего вызывающий код продолжал запрос уже с cookie исходного аккаунта. Это нарушало привязку Qwen-треда к аккаунту и могло ломать незавершённую tool-цепочку при failover.

- Добавлен регресс: для выбранного `account-b` список кандидатов создания чата обязан быть ровно `[account-b]`; верхнеуровневое создание без выбранного аккаунта по-прежнему видит ограниченный пул.
