# Обычный ChatGPT web relay — текущая простая карта

Это вспомогательный механизм ради автономности, а не новый главный продукт. Qwen / Notion / Kontur остаются главной работой.

## Идея

Внешний исполнитель пишет новое пользовательское сообщение прямо в заранее выбранный обычный чат `chatgpt.com`, чтобы дать этому чату ещё один ход работы без участия владельца.

Это НЕ OpenAI API и НЕ Work mode. Это обычный ChatGPT web UI под собственной авторизованной сессией владельца.

## Как теперь мгновенно будится relay

Отдельная relay-ветка сама CircleCI не будит. Поэтому одна команда состоит из двух связанных маленьких изменений:

1. На relay-ветке появляется outbox:
   - `enabled=true`;
   - уникальный `id`;
   - уникальный `trigger_nonce`;
   - текст команды.
2. В доказанно работающей Qwen-ветке меняется `.relay-trigger/chatgpt-web-relay.txt` на тот же nonce, а commit обязан называться ровно:
   `relay-trigger: <тот-же-nonce>`.

Именно этот второй commit сразу будит существующий Qwen CircleCI.

Pulse отправляет сообщение ТОЛЬКО если одновременно:
- outbox включён;
- `trigger_nonce` валиден;
- текущий Qwen commit имеет точный subject `relay-trigger: <nonce>`;
- `.relay-trigger/chatgpt-web-relay.txt` содержит тот же nonce.

Любой следующий обычный Qwen commit получает `trigger_mismatch` и не открывает ChatGPT, даже если старый outbox ещё `enabled=true`.

Это убирает две проблемы сразу: команда не ждёт случайного Qwen-коммита и не начинает повторно будить ChatGPT на каждом последующем изменении проекта.

## Доступ к ChatGPT

Не хранить отдельный открытый `CHATGPT_TOKEN`.

Переносимое состояние браузерной сессии — cookies + web storage/IndexedDB + URL выбранного чата — хранится только в зашифрованном виде:

`.runtime-state/chatgpt-web-session-v1.json.gpg`

Через существующий Git LFS.

Предпочтительный ключ — уже существующий CircleCI secret `RUNTIME_STATE_KEY`.

Если старый Qwen key локально физически не найден, предусмотрен запасной `CHATGPT_RUNTIME_STATE_KEY`.

По состоянию на 2026-08-19 encrypted ChatGPT session ЕЩЁ НЕ создана/не опубликована. Это единственный кусок, который нельзя изготовить без одноразового входа владельца в собственный ChatGPT на ПК.

## Защита от повторной отправки

Каждое внешнее сообщение получает `[relay-id:<уникальный-id>]`.

Перед отправкой браузер ищет этот id среди последних пользовательских сообщений в целевом чате. Если он уже там — повторной отправки нет, даже если предыдущая попытка успела написать сообщение, но потеряла внешний журнал.

Успех считается только если:
1. новое пользовательское сообщение реально появилось в DOM целевого чата;
2. после него реально начался новый assistant-turn.

Текст ответа для подтверждения старта не читается.

Issue `#11` остаётся необязательным журналом. На текущей маленькой Qwen job GitHub callback-token не виден, поэтому отсутствие комментария там НЕ является ошибкой relay. Сам CircleCI job и relay-id в целевом чате — основные доказательства.

## Первый реальный тест, когда будет ПК

Нужен один человеческий вход:

1. Открыть локально ветку `autopilot/chatgpt-web-relay-20260819`.
2. Дважды кликнуть `CHATGPT_RELAY_FIRST_TEST.cmd`.
3. В отдельном Chromium войти в СВОЙ ChatGPT.
4. Просто открыть выбранный обычный чат `https://chatgpt.com/c/...`.
5. Всё остальное делает скрипт: захват -> шифрование -> удаление plaintext -> push encrypted bundle/outbox -> одноразовый trigger-коммит в Qwen -> CircleCI.
6. CircleCI должен открыть тот же чат и отправить `CHATGPT_RELAY_TEST_... [relay-id:...]`.
7. Relay ждёт факт старта нового ответа ассистента.

Если старый Qwen runtime key найден локально — новый секрет вообще не нужен. Если не найден — скрипт остановится ДО входа в ChatGPT и попросит один раз положить созданный ключ в CircleCI под именем `CHATGPT_RUNTIME_STATE_KEY`.

## После первого PASS

Scheduled Task / Qwen / Notion сможет автономно делать ту же двухкоммитную операцию: outbox с nonce -> trigger-коммит с тем же nonce. CircleCI сразу доставит короткую команду в обычный ChatGPT-чат.

Приватный большой системный промпт владельца в GitHub не нужен: он может оставаться только внутри целевого обычного чата. Relay отправляет короткие команды продолжения.

Главный смысл: меньше времени, когда система ничего не делает только потому, что очередной Scheduled Task уже завершился.
