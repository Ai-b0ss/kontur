## Что уже есть

- локальные CAPTCHA/rate limit/expired auth не останавливают весь пул: бюджет переключений по умолчанию 4, жёсткий потолок 6;
- provider-wide WAF/trust restriction, provider pressure и неоднозначный timeout останавливают дальнейшее прощупывание соседних аккаунтов;
- новый независимый запрос выбирает давно не использовавшийся подходящий аккаунт, а существующий Qwen-тред сохраняет приоритет своего аккаунта-владельца;
- при failover незавершённой цепочки создаётся свежий Qwen-тред и один раз переносится полная локальная история;
- tool-loop продолжает работу после tool result и исправимых ошибок инструмента; обычный лимит 12 модельных ходов, жёсткий потолок 24;
- два режима системного промпта (`engineer`/`owner`) и локальные Skills уже есть;
- account JSON, основной session checkpoint и backup сохраняются crash-safe;
- provider circuit записывается и очищается транзакционно; соседний рабочий после прошлой смены добавил откат прежних байтов и при неудачном durable `trip()`;
- появился первый ограниченный локальный диспетчер субагентов: до 4 изолированных задач, последовательный режим по умолчанию, максимум 2 параллельно только явно; каждая задача получает отдельный session id и может выбрать Skills;
- ChatGPT relay не активная задача до появления owner session; outbox не включать.

## Эта смена

- заново прочитаны owner intent, текущая карта и handoff; проверены свежие PR #6 и `qwen-workspace` PR #5;
- на старте PR #6 уже был на `dfcf897a40ccff6d07f8a7f835c5f1718ddb6dd5`: соседний рабочий трогал только `provider-circuit` и его тест, поэтому взят независимый участок расширения возможностей;
- добавлен `src/subagent-dispatcher.js`: он отправляет независимые задачи через уже существующий локальный OpenAI-compatible `/v1/chat/completions`, а значит не заводит отдельный обход пула и использует существующие cooldown/circuit/session правила;
- жёсткие ограничения: максимум 4 задачи в пачке, по умолчанию concurrency=1, абсолютный максимум concurrency=2, таймаут ограничен; provider-circuit на первой последовательной задаче прекращает дальнейшие запросы пачки;
- каждая задача получает отдельный `x-opencode-session-id`, поэтому контексты субагентов не смешиваются. Task/session id проходят строгую проверку и не могут содержать перевод строки или другие опасные символы заголовка;
- режим `owner` поддержан без смешивания с инженерной персоной: `owner_system_prompt` передаётся существующему серверному контракту как есть; Skills передаются штатным полем `skills`;
- добавлен CLI `npm run subagents`: вход — JSON через stdin или файл, выход — JSON с результатами всех задач;
- добавлен офлайн-тест `scripts/subagent-dispatcher-test.js` и включён в обычный `npm test`; он проверяет лимиты, изоляцию session id, Skills, owner-mode и остановку пачки при provider circuit;
- на самопроверке найден и сразу исправлен собственный дефект первой версии: default endpoint был ошибочно `:8000`; теперь он берётся из реального `config.PORT` (сейчас 3265);
