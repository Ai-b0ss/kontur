1. До изменений создана и проверена свежая полная резервная копия рабочей D1.
2. К production применены только добавочные миграции `0003`–`0005`; старые
   миграции не редактировались.
3. Код опубликован без `EXPERIENCE_V2_ENABLED` и списка участников.
4. В выключенном состоянии авторизованный старый API ответил `200`, новый —
   `404 EXPERIENCE_DISABLED`; существующий пользователь сохранился.
5. После отдельной проверки новый путь включён только для единственного уже
   существующего внутреннего аккаунта. Telegram ID не выводился и не попал в
   документы.
6. Подключён только настроенный основной чат. Специальный чат не подключён:
   точного рабочего chat ID в конфигурации нет.
7. После миграций и после внутреннего smoke созданы ещё две полные резервные
   копии.

- прежний авторизованный `/api/v1/state`: `200`;
- при выключенном флаге `/api/v2/state`: `404 EXPERIENCE_DISABLED`;
- после включения для внутреннего списка `/api/v2/state`: `200`;
- выключение и повторное включение проверены вживую;
- webhook остался на прежнем адресе, очередь равна нулю, последней ошибки нет;
- пять прежних команд бота сохранены;
- новый интерфейс открылся на 390 px без горизонтальной прокрутки и ошибок;
- архив прежней версии доступен только для чтения;
- синтетический вопрос дошёл до предпросмотра, пережил обновление страницы и
  был закрыт без отправки сообщения в Telegram;
- после smoke в новых таблицах нет напоминаний или повторных запросов; остался
  один закрытый технический путь как свидетельство проверки.

Проверка выполнялась с подписанным Telegram initData внутреннего аккаунта, но
без чтения переписки, Telegram ID и содержания настоящих сообщений.

## Быстрое выключение

Сначала сухой прогон:

```powershell
pwsh -NoProfile -File tools/cloudflare-v2-disable.ps1 `
  -ProxyUrl http://127.0.0.1:7890
```

Реальное выключение:

```powershell
pwsh -NoProfile -File tools/cloudflare-v2-disable.ps1 `
  -ProxyUrl http://127.0.0.1:7890 -Apply
```

Выключение не удаляет таблицы и не откатывает миграции: оно только закрывает
новый путь, поэтому старый интерфейс снова становится основным.

## Наблюдение до решения

В Codex создан ежедневный read-only монитор на семь запусков в 10:30 МСК. Он
не отправляет сообщения и не меняет Worker, D1, webhook, секреты или список;
уведомление требуется только при сбое. Последний запуск должен подготовить
итог и остановиться перед расширением.

Проверять без содержания сообщений:

- health, ошибки Worker и состояние webhook;
- число начатых, закрытых и сохранённых путей;
- повторные запросы и технические ошибки;
- наличие напоминаний только после явного согласия;
- неизменность старых игровых начислений для участника новой версии;
- понятность первого экрана на настоящих Telegram Desktop, iOS и Android.

## Что ещё не выполнено

- пять независимых людей не прошли проверку понятности — `NOT RUN`;
- настоящий Telegram-путь с вопросом, ответом и `/worm` не пройден — сообщения
  намеренно не отправлялись;
- специальный чат не подключён — `HOLD` до точного chat ID;
- семь дней наблюдения не истекли;
- расширение списка и итоговое решение запрещены до конца наблюдения.

Текущий запуск нельзя называть общим релизом: это один внутренний аккаунт и один
основной чат.
