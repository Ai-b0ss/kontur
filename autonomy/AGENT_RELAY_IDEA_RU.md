# Обычный ChatGPT web relay — текущая простая карта

Это вспомогательный механизм ради автономности, а не новый главный продукт. Qwen / Notion / Kontur остаются главной работой.

## Зачем

Пять Scheduled Tasks дают пять периодических пробуждений, но отдельный запуск может закончиться рано. Relay нужен, чтобы внешний исполнитель мог написать новое пользовательское сообщение прямо в заранее выбранный обычный чат `chatgpt.com` и дать этому чату ещё один ход работы без участия владельца.

Это НЕ OpenAI API и НЕ Work mode. Это обычный ChatGPT web UI под собственной авторизованной сессией владельца.

## Доступ к ChatGPT

Не хранить отдельный открытый `CHATGPT_TOKEN`.

Переносимое состояние браузерной сессии — cookies + web storage/IndexedDB + URL выбранного чата — хранится только в зашифрованном виде:

`.runtime-state/chatgpt-web-session-v1.json.gpg`

Через существующий Git LFS.

Предпочтительный ключ — уже существующий CircleCI secret:
`RUNTIME_STATE_KEY`.

Если старый Qwen key локально физически не найден, предусмотрен запасной:
`CHATGPT_RUNTIME_STATE_KEY`.

По состоянию на 2026-08-19 encrypted ChatGPT session ЕЩЁ НЕ создана/не опубликована. Это единственный кусок, который нельзя изготовить без одноразового входа владельца в собственный ChatGPT на ПК.

## Защита от дублей

Каждое внешнее сообщение получает:
`[relay-id:<уникальный-id>]`.

Перед отправкой браузер ищет этот id среди последних пользовательских сообщений в целевом чате. Если он уже там — повторной отправки нет, даже если прошлый CircleCI успел написать сообщение, но не успел отметить доставку где-либо ещё.

Успех считается только если:
1. новое пользовательское сообщение реально появилось в DOM целевого чата;
2. после него реально начался новый assistant-turn.

Текст ответа для подтверждения старта не читается.

## Что сейчас физически безопасно

`relay/outbox.json` пока `enabled=false`.
Encrypted ChatGPT session отсутствует.

Поэтому текущий relay НЕ МОЖЕТ отправить сообщение в обычный ChatGPT. Сейчас он только проходит офлайн-проверку на уже работающей CircleCI-машине Qwen.

## Первый реальный тест, когда будет ПК

Нужен один человеческий вход:

1. Открыть локально ветку `autopilot/chatgpt-web-relay-20260819`.
2. Дважды кликнуть `CHATGPT_RELAY_FIRST_TEST.cmd`.
3. В отдельном Chromium войти в СВОЙ ChatGPT.
4. Просто открыть выбранный обычный чат `https://chatgpt.com/c/...`.
5. Ничего больше в консоли подтверждать не нужно: скрипт сам увидит чат.
6. Он сохраняет переносимое состояние, шифрует его, удаляет plaintext и публикует encrypted bundle + уникальный тестовый outbox.
7. Следующий обычный Qwen CircleCI pulse должен открыть тот же чат и отправить `CHATGPT_RELAY_TEST_... [relay-id:...]`.
8. Relay ждёт факт старта нового ответа ассистента.

Если старый Qwen runtime key найден локально — новый секрет вообще не нужен. Если не найден — скрипт остановится ДО входа в ChatGPT и попросит один раз положить созданный ключ в CircleCI под именем `CHATGPT_RUNTIME_STATE_KEY`.

## После первого PASS

Scheduled Task / Qwen / Notion сможет оставлять короткое новое задание в `relay/outbox.json`, а уже существующий Qwen CircleCI pulse доставит его в обычный ChatGPT-чат.

Приватный большой системный промпт владельца в GitHub не нужен: он может оставаться только внутри целевого обычного чата. Relay отправляет короткие команды продолжения.

Главный смысл: меньше времени, когда система ничего не делает только потому, что очередной Scheduled Task уже завершился.
