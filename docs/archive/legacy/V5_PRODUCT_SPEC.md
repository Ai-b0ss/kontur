# Контур V5 — спецификация живой кампании

Статус: **рабочая спецификация, 2026-08-07**. Она фиксирует согласованный
перезапуск и не меняет V1–V4. До remote-миграции и выпуска нужны отдельные
Git/D1 checkpoints.

## 1. Обещание игроку

**За минуту ты совершаешь ход своей птицей: решаешь короткую связку задач в
единственной объявленной цели окна и сразу видишь личный след в общей
кампании.**

Это игра для участника, который не помогает другим, не пишет в чат и не
собирает команду: у него есть птица, коллекция форм, личные предметы,
прогнозы и заметный результат собственного хода. Команда и чат усиливают
ощущение кампании, но не являются входным билетом.

## 2. Границы продукта

- Один живой Telegram-чат — сцена; Mini App — личная база.
- V5 не читает поток чата, не считает сообщения и не оценивает людей.
  Единственный пользовательский сигнал — явный ответ на пост Контура или
  команда `/kontur`; исходный текст не сохраняется как игровой профиль.
- V5 не является FAQ, техподдержкой, навигатором абитуриента или taskboard'ом
  поручений людей.
- Одна кампания длится **28 суток** и стартует из детерминированного
  каталога следующей; профиль, птицы, перья и предметы живут месяцами.
- В одном чате открыто максимум одно событие. Обычный ритм — три окна в
  неделю, каждое открыто до восьми часов. Это не ежедневная контент-фабрика.
- Бот публикует максимум один главный пост на открытие и, при необходимости,
  один короткий итог. До явного включения публикации для V5 бот не пишет ни
  в основной чат, ни в тестовый сам.
- V1, V2, V3 и V4 не получают новых зависимостей, миграций или изменений
  поведения. V5 запускается только через отдельные feature gates, `/api/v5`
  и `?campaign=v5`.

## 3. Птица и постоянный рост

Претест — шесть ситуационных выборов и tie-breaker только при равенстве.
Он проверяет предпочитаемый способ решать задачу, а не знания и не профессию.
Результатом становится одна базовая птица I формы:

| Направление | Базовая птица | Что предпочитает в игре |
| --- | --- | --- |
| системы | Дятел | цепочки, условия, сборка решения |
| визуальный синтез | Сорока | понятность, интерфейс, выбор для человека |
| анализ | Сова | гипотеза, факт, вывод из данных |
| организация | Журавль | зависимость, порядок, ограничение |

У игрока может быть несколько птиц, но одна активна в кампании. Перед первым
ходом кампании он выбирает активную; после него переключение запирается до
следующей кампании. В запущенной сессии всегда фиксируется именно эта птица.

Успешная серия даёт активной птице одно перо пути, не более одного за событие.
На восьми перьях игрок без чужой помощи выбирает линьку:

1. улучшить ту же птицу до формы II;
2. открыть другую птицу сразу во II форме.

Выбор необратим, но исходная птица не исчезает. Форма II не является
числовым усилением всего: у неё один signature maneuver на кампанию с
серверным потолком `+1` к выбранной шкале события. Манёвр не меняет ответы,
не открывает вторую попытку, не даёт яйца и не влияет на чужие результаты.

## 4. Дерево и реальная макро-игра

В кампании есть семь секторов дерева. Сектор проходит наблюдаемые состояния:

```text
hidden → exposed → secured → rooted
```

Плановый шторм понижает сектор на одну ступень, если на нём нет ward; один
ward расходуется вместо понижения. Личный прогресс птицы никогда не теряется.
Так у трёх действий есть разные, проверяемые причины существовать:

| Действие | Когда разумно | Серверный эффект при достаточной общей силе |
| --- | --- | --- |
| `scout` | соседний путь скрыт либо идёт неизвестный шторм | раскрывает соседний сектор и следующий риск |
| `claim` | открыт новый сектор | переводит `exposed → secured`, открывает маршрут |
| `hold` | ценный сектор может потерять ступень | кладёт ward; без шторма помогает `secured → rooted` |

Сражение идёт против состояния дерева и шторма, а не против конкретных людей.
Это даёт борьбу и макрорешение, но не строит токсичный рейтинг участников.

В каждом окне сервер объявляет одну законную пару `sector + action`. Игрок не
перебирает произвольные клетки ради оптимума: он выбирает, вложить ли свой
единственный ход, предмет и манёвр в эту цель. Ответы `/kontur scout|claim|hold`
на игровой пост могут назначить разрешённую цель следующего свободного окна.

При открытии сервер рассчитывает три порога из числа разных активных игроков
за последние семь суток:

```text
threshold = clamp(3, 12, 2 + ceil(activePlayers7d / 3) + eventTier - 1)
```

После двух нерешённых окон safety rail оставляет один `exposed` сектор без
отката: маленький чат не может навсегда застрять. Вклад одного игрока всегда
имеет потолок `2`; массовая автоматизация не превращает 250 участников в
безусловный каток.

## 5. Один ход: пять карточек, 75 секунд

Игрок до старта выбирает предмет и, если доступен, манёвр для уже объявленной
сервером пары `event + sector + action`. Сервер создаёт единственную сессию с
seed и дедлайном 75 секунд. В ней ровно пять
коротких последовательных карточек:

1. базовый образовательный вопрос: ЕГЭ-база, логика или цифровая грамотность;
2. прикладной образовательный вопрос по активной птице;
3. микрозадача «сигнальная цепь» — выбрать работающую последовательность
   условий/действий;
4. тактическая карточка, использующая актуальное состояние карты;
5. финальная проверка риска или ограничения текущего события.

Правильные ответы, варианты и seed клиент не получает до подведения итога.
Скорость не даёт очков или редкости: таймер только обрывает позднюю попытку.
Пять решений дают серверный `evidenceScore`:

| Условие | Вклад в выбранную шкалу |
| --- | ---: |
| 0–1 верных | 0 |
| 2–3 верных | 1 |
| 4–5 верных и верна тактическая карточка | 2 |
| 4–5 верных, но неверна тактическая карточка | 1 |

Так поиск двух фактов или ответ одной модели не гарантирует лучший результат:
для максимального вклада нужны микрозадача и выбор, связанный с картой.
Сервер принимает ответ только до собственного `closeAt`; открытый клиентский
экран после срока ничего не меняет.

После результата Mini App показывает строго три вещи: личный вклад, изменение
птицы/предмета и то, как этот вклад вошёл в шкалу сектора. Он не раскрывает
чужие ответы, составы и незакрытые шкалы.

## 6. Простая экономика

Нет магазина, доната, рынка, передачи или случайного pay-to-win.

- **Перья пути** — постоянный прогресс к форме II; максимум одно за событие.
- **Яйца** — только расходник для прогнозов. Их нельзя подарить, купить или
  продать.
- **Предметы** — максимум три занятых слота; они одноразовые, неторгуемые и
  выбираются до старта. Переполненный инвентарь требует заменить предмет или
  отказаться от нового.

Первый релиз содержит четыре предмета с реальным, но ограниченным смыслом:

| Предмет | Когда вооружается | Максимальный эффект |
| --- | --- | --- |
| Точильное перо | `claim` с базовым вкладом `1` | усиливает его до `2`, не создаёт второе перо |
| Смола гнезда | успешный `hold` | один дополнительный ward |
| Линза | перед серией | раскрывает правило микрозадачи, не ответ |
| Сигнальная нить | успешный `scout` | `+1 scout`, один раз |

Предмет привязывается атомарно к единственной сессии. Линза расходуется сразу,
потому что уже показала правило; несыгравший предмет возвращается при timeout
или закрытой цели. Полный инвентарь не создаёт четвёртый слот: новая рейдовая
награда просто не выдаётся. Предмет не исправляет неверный ответ и не даёт
второй ход.

## 7. Прогнозы и рейды

Прогноз — анонимная ставка ровно одного яйца на безопасный игровой исход:
например, будет ли закрыт `claim` порог выбранного сектора. Никогда нельзя
прогнозировать человека, число его сообщений, мат, деньги или внешний факт.

- Один прогноз на событие.
- Окно закрывается по `forecastDeadline` **и сразу после первого начатого
  хода** в этой цели; это проверяет SQL-trigger, а не только клиент.
- Повтор возвращает уже зафиксированный выбор и не списывает второе яйцо.
- Верный прогноз возвращает два яйца, неверный — ноль, `void` — исходное яйцо.

Рейд появляется не чаще одного раза в три события. Игрок добровольно встаёт
в очередь на конкретную цель; состав `4–6` фиксируется только при готовности.
После готовности каждый самостоятельно проходит отдельную двухкарточную
роль. Успех требует не менее 60% валидных вкладов и нужных ролей
`scout/claim/hold`; награда — один предмет и дополнительный маршрут, но не
второй ход и не двойное перо.

Очередь рейда **не блокирует соло-ход**. Если до дедлайна собралось меньше
четырёх, она растворяется без потери яйца, предмета или права играть соло.

## 8. Голос Telegram и LLM

Групповой пост не содержит `web_app`-кнопку: Telegram поддерживает такую
кнопку только в личном чате с ботом. Путь игрока:

```text
пост Контура в группе
  → deep link личному боту с event id
  → /start v5_<event> в личке
  → личная web_app-кнопка
  → ?campaign=v5&event=<event>
```

Ответ на пост Контура с `/kontur <тип>` создаёт только добровольный контракт
следующего свободного окна. Сохраняются ID исходного сообщения и разрешённый
тип; обычные сообщения чата не сканируются.

LLM — необязательный режиссёр. Он может выбрать из server-side каталога
шаблон, safe-тему, заголовок, одну строку подачи и итог по уже рассчитанному
JSON. Он не видит обычный чат и не может выбрать вопросы, пороги, ответ,
награду, баланс или отправку сообщения. На таймауте, rate limit или невалидном
JSON сразу используется статический шаблон.

Поддерживаемые режимы: `disabled`, встроенный `cloudflare`, позднее внешний
`groq`. В релизе игра полностью работает с `disabled`; ключ хранится только
в Worker secret, не в клиенте, репозитории или Telegram.

## 9. Неподменяемые переходы и антиабуз

| Сущность | Переход |
| --- | --- |
| профиль | `none → claimed`; повтор возвращает исходный результат |
| птица | `I → II`; в кампании активна ровно одна |
| событие | `scheduled → open → locked → resolved` |
| сессия | `none → started → settled/timed_out`; submission хранится отдельной immutable-записью |
| ход | один на `(user, event)` независимо от нового request ID |
| прогноз | `available → pending → won/lost/void`; отмены нет |
| предмет | `owned → armed → consumed/released` |
| рейд | `queued → ready → resolved` либо `withdrawn/dissolved` |

Каждый write имеет серверный уникальный ключ. Второй `clientRequestId` не
создаёт вторую сессию; атомарный первый старт закрепляет вариант на сервере.
Resolver и cron делают compare-and-swap и сохраняют итог. Telegram outbox
использует уникальный `(event_id, kind)` и при неизвестном результате отправки
предпочитает пропустить повтор, а не заспамить чат.

## 10. Обязательные acceptance checks

1. Параллельные старты одного игрока с разными request ID создают одну сессию.
2. Параллельные submit не дают двойную карту, перо, яйцо или предмет.
3. Поздний серверный submit становится нулевой попыткой.
4. Перезапуск Mini App/смена устройства возвращает тот же seed и варианты.
5. `scout`, `claim`, `hold` меняют разные поля карты по отдельным тестам.
6. Игрок получает форму II без рейда и чужой помощи.
7. Рейд из трёх растворяется, а соло-серия остаётся доступна.
8. Прогноз после первого влияющего старта и повторный прогноз отвергаются.
9. Повтор cron создаёт максимум один пост открытия и один итог.
10. Невалидный LLM JSON, timeout и выключенный ключ запускают fallback без 5xx.
11. Симуляции на 3, 20 и 250 активных игроках не deadlock-ят дерево; нет
    действия или формы с ожидаемым преимуществом более 10%.
12. Выключение только V5 gate сохраняет все V1–V4 health/API/launch paths.
13. Два одновременных Form-II запроса одной птицы оставляют одну линьку,
    форму II и ноль потраченных перьев ровно один раз.
14. Два одновременных последних вклада создают не более одного applied action:
    проигравший становится `void`, не меняет карту и не получает награду.
15. Брошенная сессия и сессия, ставшая `void`, не оставляют предмет `armed`;
    cron завершает её как `timed_out`.
16. Одновременные входы в рейд получают роли из атомарного server-side count;
    успешный рейд содержит все три роли и не превышает шести участников.
