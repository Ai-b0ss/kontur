# КОНТУР — выравнивание таксономии результата

**Дата:** 2026-08-14  
**Статус:** ПРИНЯТО OWNER; подготовка к официальному STEP F / PREVIEW  
**Baseline:** v84 + принятые STEP A–E

## Решение

Внутренних ролей по-прежнему **пять**. Визуальных результатов становится **шесть**.

Котосов не является шестой ролью и не конкурирует с `designer / coder / creative / manager / vibe`. Он является presentation-only подтипом уже победившей роли `vibe`: **вайбкодер**.

| Канонический результат | Визуальный результат | Правило |
|---|---|---|
| `designer` | сорока | прямое соответствие |
| `coder` | дятел | прямое соответствие |
| `creative` | сойка | прямое соответствие |
| `manager` | журавль | прямое соответствие |
| `vibe` | Котосов | `coder` — строго самый сильный вторичный score |
| `vibe` | сова | все остальные `vibe`-профили, ничья или неполные scores |

## Почему именно так

- Сова и Котосов остаются отдельными персонажами.
- Котосов считывается именно как **вайбкодер**, а не как общий `vibe`.
- Победитель `resolveRole()` никогда не меняется.
- Правило использует уже рассчитанные canonical scores и не дублирует веса вопросов.
- Строгое превосходство защищает от случайного назначения Котосова при ничьей.
- Если score vector недоступен, безопасный fallback — сова, а не выдуманный пересчёт.

## Интеграционный контракт

```js
const resolvedRole = resolveRole(scores); // существующий код, без изменений
const visualResult = selectBirdResult({ resolvedRole, scores });
```

`selectBirdResult()` вызывается **после** существующего scoring. Он не получает ответы, не знает индексов опций и не имеет собственных весов.

## Что запрещено на интеграции

- добавлять `kotosov` в canonical role weights;
- менять восемь вопросов, семантику или индексы ответов;
- менять `resolveRole()` или backend scoring;
- восстанавливать веса по текстам текущего визуального прототипа;
- назначать Котосова случайно;
- подменять сову Котосовым для всех `vibe`-результатов.

## Реализовано в этом гейте

- чистый модуль `result_taxonomy.mjs`;
- тесты прямых соответствий;
- тест `vibe + unique coder secondary → kotosov`;
- тесты ничьей, другого secondary-профиля и отсутствующих scores;
- явная ошибка на неизвестной внутренней роли.

## Сохранение результата Котосова

Backend по-прежнему хранит роль `vibe`; отдельная шестая роль не добавляется. Чтобы после перезагрузки Котосов не превращался в сову, frontend должен сохранить только presentation-вариант (`kotosov` или `owl`) в локальном хранилище с привязкой к `player.userId`.

- источник решения при первом hatch — canonical `resolveRole(answers).scores`;
- серверный `result.role` остаётся главным результатом;
- если локальный и серверный resolved role расходятся, Котосов не назначается;
- при отсутствии сохранённого варианта используется сова;
- backend, API, D1 и scoring не расширяются.
