# Qwen — агентное ядро

## 2026-08-19

`qwen-free-api`: PR #6, ветка `autopilot/qwen-runtime-preflight-20260818`, текущий head `8c77bc97c6e53bd5330e97b0a2c2e52226d9c958`.

Сделано:
- Добавлен бесплатный CircleCI-прогон полного офлайн-регресса на каждый commit ветки. На точном head `8c77bc97…` он зелёный: workflow `874faef7-99c6-4165-97b0-1bd74e87d43d`, job `f89d5ee7-5cea-4e4c-b468-05aa7e096241`. Старый «красный полный regression» на текущем коде не воспроизводится; CAPTCHA-ротация не откатывалась.
- Добавлен офлайн-тест настоящего агентного цикла: один upstream-thread, три модельных раунда, два последовательных tool result и финальный ответ. Он входит в `npm test` и прошёл в полном CircleCI-регрессе.
- Живой canary усилен: маркер генерируется только на runner; Qwen обязан сначала прочитать его через `read_file`, затем уже после результата отдельным следующим модельным ходом передать точный маркер в `bash`, получить второй tool result и только потом закончить задачу. Поэтому следующий live-прогон будет проверять именно многошаговое продолжение, а не один tool call.
- Сделаны два режима системного промпта. `engineer` по умолчанию добавляет наш базовый промпт автономного разработчика. `owner` не добавляет эту персону: явный `owner_system_prompt` проходит без переписывания; для OpenCode режим выбирается заголовком `x-qwen-system-prompt-mode: owner`, а из его системного сообщения берётся только приватный блок `<mcp_instructions>`, без встроенной персоны OpenCode и без `Instructions from:`. Технический tool-envelope остаётся отдельно. Это покрыто отдельным тестом в `npm test`.
- Добавлен `opencode.example.jsonc` с двумя готовыми провайдерами: обычный инженерный и owner-passthrough.
- Исправлен будущий live-soak: CAPTCHA ошибочно отправляла аккаунт в cooldown на 600 минут вместо 10. Теперь CAPTCHA = 10 минут, RateLimit = 360 минут. Внешний timeout canary поднят до 260 с при внутреннем 240 с, чтобы ошибка успевала классифицироваться. Добавлен офлайн-тест этой политики.
